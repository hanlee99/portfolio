🔧 핵심 문제 해결 경험

1. 외부 API 데이터 통합 및 매칭 전략

🎯 문제 KOBIS와 KMDB API의 제목 표기 차이로 매칭 실패. 초기 매칭률 90%.
💡 해결 1. Adapter 패턴으로 외부 API 격리
2. KMDB 데이터 703건 선수집
3. 2단계 매칭 전략: 정확 매칭 → 공백 제거 LIKE 검색
4. 로깅으로 "코렐라인", "가타카" 등 재개봉 영화 누락 발견 및 추가
✅ 결과: 매칭률 90% → 100% 달성

2. N+1 쿼리 문제 해결

🎯 문제 영화 상세 페이지에서 출연진마다 개별 쿼리 발생 (영화 1개 + 출연진 7명 = 8개 쿼리).
💡 해결 1. Hibernate SQL 로그로 문제 확인
2. fetch join으로 MovieEntity → MoviePersonEntity → PersonEntity 한 번에 조회
3. DISTINCT로 중복 제거
4. 상황별 Repository 메서드 분리 (findById / findByIdWithPeople)
✅ 결과: 쿼리 수 8개 → 1개 (87% 감소)

3. 캐싱 전략으로 API 호출 최적화

🎯 문제 KOBIS API 호출 시 평균 1.5-2초 소요. 박스오피스는 하루 단위 업데이트.
💡 해결 1. Spring Cache (@Cacheable) 적용
2. 날짜별 캐시 키 관리
3. 1일 TTL 설정
✅ 결과: 응답속도 1.77초 → 0.5초 (72% 개선), API 호출 80% 감소

4. JsonNode → DTO 구조 리팩토링

🎯 문제 JsonNode로 API 응답 직접 파싱. 필드명 오타 위험, 타입 안정성 없음.
💡 해결 1. 외부 API DTO / 내부 Entity 분리
2. Mapper 계층 도입
3. @JsonProperty로 필드명 매핑
4. 3일간 전체 구조 리팩토링
✅ 결과: 타입 안정성 확보, API 변경 영향 최소화

5. DB 구조 정규화 (영화-영화인 관계)

🎯 문제 영화 Entity에 출연진 직접 저장 → 배우 중복, Entity 비대화.
💡 해결 1. Person Entity 생성 (영화인 정보 통합)
2. MoviePerson Entity (중간 테이블)
3. 다대다 관계 설계
✅ 결과: 데이터 중복 제거, 영화인 정보 재사용, 703개 영화 + 5,532명 관리

• Repository: 데이터 접근

• 의존성 역전: 외부 API → Adapter
