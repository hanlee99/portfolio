🏗️ 아키텍처 특징:
• Layered Architecture: Controller → Service → Repository 계층 분리
• Adapter Pattern: 외부 API 통합 시 어댑터 패턴 적용
• Entity의 캡슐화 강화: 변환 로직을 Entity가 책임지도록 설계
• 책임 분리: Service 분리(MovieService/MovieSyncService)로 SRP 준수

🎯 핵심 설계 포인트

1. Adapter 패턴으로 외부 API 격리

KOBIS, KMDB API를 Adapter로 감싸 Service가 외부 API 형식에 의존하지 않도록 설계. API 변경 시 Adapter만 수정하면 되어 유지보수성 향상.

2. Service 중심 오케스트레이션

모든 비즈니스 로직이 Service를 거치도록 설계. Adapter, Mapper, Repository는 Service만 접근하여 의존성 방향이 명확하고 순환 참조 방지.

3. DTO 계층 분리

Entity와 DTO를 명확히 분리하여 API 스펙 변경 시 Entity에 영향 없음. Request/Response DTO로 계층간 결합도 최소화.

4. 책임 분리 (SRP)

MovieService(조회/검색)와 MovieSyncService(동기화/저장)로 분리하여 Command/Query 책임을 나누고 각 Service를 120줄 이내로 유지.

🎯 Problem Solving:

1. API 응답 지연 개선
• 문제: KMDB API 호출 시 3초 이상 소요
• 해결: 영화 기본 정보를 DB에 캐싱, 필요 시에만 API 호출
• 결과: 평균 응답 속도 50% 개선

2. 외부 API 장애 대응
• 문제: KOBIS API 일시적 장애 시 서비스 중단
• 해결: 예외 처리 + DB에 저장된 최근 데이터 제공 (Fallback)
• 결과: 서비스 가용성 99% 이상 유지
