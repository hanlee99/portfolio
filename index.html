🏗️ 시스템 아키텍처

📋 계층별 역할

  • Presentation Layer: HTTP 요청/응답, REST API 엔드포인트, View 렌더링
  • Business Layer: 비즈니스 로직, 트랜잭션 관리, 캐싱 전략
  • Adapter Layer: 외부 API 호출, 외부 응답 → 내부 DTO 변환
  • Persistence Layer: JPA 기반 데이터 접근, Entity ↔ DTO 변환

🗄️ 데이터베이스 설계

영화-영화인 다대다 관계, 극장-특별관 관계 등 총 7개 엔티티로 구성

⚙️ 주요 구현 사항

1. 외부 API 통합 흐름

KMDB API → Adapter 변환 → Entity 저장 → DB
KOBIS API → Adapter 변환 → DB 매칭 → 통합 DTO → Controller

2. N+1 쿼리 최적화

  • 문제: 영화 상세 조회 시 출연진마다 개별 쿼리 발생
  • 해결: LEFT JOIN FETCH로 한 번에 조회
  • 결과: 쿼리 수 대폭 감소, 응답 시간 개선

3. 보안 체계

  • Spring Security: /admin/** 경로 ADMIN 역할 인증 필요
  • BCrypt: 관리자 비밀번호 암호화
  • 환경변수: API 키 및 관리자 인증 정보 분리

4. 캐싱 전략

  • Caffeine: 박스오피스 데이터 인메모리 캐싱
  • 관리자 API: 수동 캐시 삭제 → 다음 요청 시 자동 갱신
  • 결과: 중복 API 호출 제거, 응답 속도 개선

🔧 문제 해결 경험

1. 한글 인코딩 깨짐
• 문제: KMDB API 응답 한글이 깨져 영화 제목 매칭 실패
• 해결: UTF-8 강제 설정 + trim() 처리로 정규화
• 결과: 영화 제목 매칭 정확도 향상

2. Tailwind CSS 충돌
• 문제: 전역 CSS와 Tailwind 클래스 충돌로 UI 깨짐
• 해결: 전역 규칙 제거 → Tailwind 일원화
• 결과: 모든 화면 크기에서 일관된 UI

3. JsonNode → DTO 리팩토링
• 문제: 필드명 오타 위험, API 변경 시 영향 범위 불명확
• 해결: DTO/Entity 계층 분리, Mapper 도입
• 결과: 타입 안정성 확보, 유지보수성 향상
